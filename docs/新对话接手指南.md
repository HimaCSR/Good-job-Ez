## 一、这是什么

**好岗好找 / Good-job-Ez** —— Hermes 的招聘岗位雷达插件。

定时抓取 BOSS 直聘 / 智联招聘 → 按用户画像本地打分 → 生成日报 → 推送到 QQ。
附带桌面端设置页、简历匹配优化、投递闸门。

| | |
| --- | --- |
| 仓库 | 本仓库（clone 后即是）。本机位置在 `AGENTS.md` 的说明里 |
| 远程 | `https://github.com/HimaCSR/Good-job-Ez.git`（main，已推） |
| agent 半边 | `src/job_radar/`（Python，跑在 Hermes 网关里） |
| 桌面半边 | `src/job_radar/desktop/plugin.js`（React，设置页） |
| 数据 | `<HERMES_HOME>/plugin-data/job-radar/`（jobs.db / profile.yaml / logs / resume） |
| 安装 | `bash scripts/dev.sh install .` |

## 二、用户的硬性要求（**别违反**）

这些是用户反复强调过的，不是我的偏好：

### 1. 简历优化**不能编造经历**

- 每条 bullet 必须能追溯到用户写过的原文
- 定位写「← 依据：经历第 N 条」，**不要把原文再贴一遍**（没信息量，还撑长简历）
- 用户不具备的技能如实列为缺口，**不编造、不暗示具备**
- 正式简历里依据标注默认隐藏（那是预览用的）

### 1.5 登录态只在浏览器里

- **插件不碰密码、不碰验证码** —— 给用户一个「打开招聘网站登录」的按钮
- 用**插件专用**的浏览器（bb-browser 起的那个），不接管用户日常 Chrome
- **别硬编码任何本机路径** —— 仓库公开给别人用，profile 目录是 bb-browser 管的
- 登录凭证值不进配置、不进 SQLite、不进日志、不进 git
- **「假成功」是最坑的**：9222 上是空 profile 时，bb-browser 照样报
  `CDP connected: yes`、抓取照样返回数据，但薪资是 `**-**元`。
  **只有看薪资打码才发现登录态没了**

### 2. 投递永远需要用户单独点头

- 抓取是只读的
- 投递是不可逆动作，必须过三道门：
  站点开关（默认关）→ 一次性令牌（5 分钟，绑定 job_id）→ 该站每日上限
- **选定历史简历 ≠ 授权投递**，选定后还要再确认一次

### 3. 只做两态，不做第三态

| 场景 | 行为 |
| --- | --- |
| 该岗位做过简历匹配优化 | 直接投优化后那份，不再问 |
| 没优化过 | 弹历史简历推荐，按对该岗的匹配分排序 |

**不要**做「没有历史简历 → 引导去优化」这个分支。用户自己会判断。

### 4. UI 布局约定

- **同类入口只留一处**（上传模板只从模板库右下角的「＋」进）
- **提示收进帮助按钮**（右上角 `?` 浮层）
- **次要设置收进「高级」按钮**（模块标题栏右上角，默认折叠）
- **重要内容放首位**（日报：今日日报在上，推送摘要在下）
- **主操作在右，次操作在左**（模板库：预览 │ 转换并加入模板库 │ 保存）
- **操作按钮同行横排**（岗位卡：分数在上，三个按钮同一行）

### 5. QQ 推送格式

每条 = 一份岗位，只含 `岗位名 · 城市` + 链接。**不带分数、不带命中理由。**
单条 ≤50 字符（URL 除外，且不得切断）。

### 6. 评分公式

```
职位名 30 + 技能 30 + 城市 20 + 薪资 20
```
（没有经验项。别自己加。）

### 7. 开源脱敏

仓库里**不得出现**：真实姓名、手机号、邮箱、本机绝对路径、真实公司名、
cookie 值、真实简历原文。

- 演示数据一律用「张三」「某人力资源有限公司」「user@example.com」
- `profile.yaml` 只提交 `profile.example.yaml`
- 提交前跑 `bash scripts/check-sensitive.sh`

### 8. 平台名与插件名

- 中文名（用户看到的）：**好岗好找**
- 仓库名：`Good-job-Ez`
- agent 端插件名：`job-radar`（`plugin.yaml` 的 `name`，也是 config 键）
  —— **改它是破坏性变更**（settings 命名空间会跟着动，老配置静默丢失）
- 工具名 `job_radar_*` 独立声明在 `provides_tools`，**别为了好看去动**
- 桌面端可以单独设显示名：`name: '好岗好找 Good-job-Ez'`

## 五、动手前必须知道的坑

> 本机的实际路径（含 Hermes 主目录、Chrome profile）**不写在这儿** ——
> 仓库要公开，那些是隐私。需要时用环境变量：
> `HERMES_HOME`（Hermes 主目录）、`LOCALAPPDATA`（Windows 本机数据）。
> Chrome 的 profile 路径在 skill `job-radar` 里。


### 结构类

| 坑 | 说明 |
| --- | --- |
| **dashboard 不能用相对导入** | Hermes 把 `dashboard/plugin_api.py` 当独立模块加载（module name = `hermes_dashboard_plugin_<name>`），没有父包。`from . import storage` 必然 ImportError。用 `_sibling("storage")` |
| **挂载 API 靠 `dashboard/manifest.json`** | 不是 `plugin.yaml`。没有 manifest.json → 路由永远不挂 |
| **config.yaml 写入必须走 CLI** | `hermes config set plugins.entries.job-radar.settings.<key> <value>`。手写 YAML 缩进错会把整个 `job-radar:` 节点变成空节点，回读全丢 |
| **CLI 位置** | `$HERMES_HOME/hermes-agent/.hermes/bin/hermes`。**不要用 `python -m hermes_cli`**（那包没有 `__main__`） |

### 开发模式

- agent 半边是 **junction** → 改代码即生效
- 桌面半边是**副本** → 改完跑 `bash scripts/dev.sh sync-desktop`
- 桌面 app 对**已加载**的插件不重读文件 → 要 ⌘K → Reload desktop plugins 或重启
- `check-repo.sh` 会检查副本漂移 + marker 在不在

### 会踩的运行时坑

| 坑 | 说明 |
| --- | --- |
| **`load_config()` 依赖 ctx** | 独立跑脚本（cron 的 no-agent 模式）时返回默认值，`keywords` 是空的 —— 看起来像配置没生效。脚本要自己读 `hermes config get` 再伪造 ctx |
| **profile 读失败会静默变空** | `load_profile()` 捕获所有异常返回 `DEFAULT_PROFILE`。文件写坏了不报错，只看起来像「用户什么都没填」。改完立刻验证能解析 |
| **JD 只在详情页** | 列表页不返回 JD。优化流程要按需 `bbclient.fetch_detail()` 抓一次 |
| **JD 的 tags 常粘连** | `CSSJavaScriptERP` → 三层切分：已知技能名 → camelCase → 全大写边界 |
| **「用于切分的词」≠「算作技能的词」** | 两张表：`SKILL_ALIASES`（真技能）+ `SPLIT_ONLY`（只提供切分边界）。混了会让缺口列表莫名其妙 |
| **插件 API 外部 curl 一律 401** | 要 native-http ticket 认证。测试绕过中间件直接调 endpoint |
| **git push 卡住先分清是凭据还是代理** | 报 `Failed to connect to port 443` → 代理问题（git 不读系统代理）。卡在等密码 → 凭据问题 |
| **`git-credential-manager get` 在 MSYS 下会挂死** | 直接用它取凭据，手动塞 `http.https://github.com/.extraheader` |
| **配置不能存嵌套字典** | `_read_config_yaml` 只认顶层 key 和顶层块序列。`apply_sites: {zhaopin: true}` 会被打散成顶层键 `zhaopin`/`boss`，读出来是错的。**用扁平键** `apply_zhaopin` / `apply_limit_zhaopin` |
| **本机是 Python 3.14，CI 是 3.11/3.12/3.13** | 3.14 的注解是惰性求值，`def f() -> List[dict]` 少了 `from typing import List` **不报错**；3.11~3.13 直接 NameError 导入失败。改完要在 3.12 上跑一遍 |
| **`with sqlite3.connect(...)` 不关连接** | `Connection.__exit__` 只提交事务，**不关连接**。24 个调用点每个漏一个句柄。用 `storage._Conn` 子类（`__exit__` 里 close） |
| **懒加载日志 handler 首次 emit 会崩** | `logging.Handler.handle()` 在 emit **之前**就 acquire 了 handler 的 lock；父类 `__init__` 在首次 emit 里才跑，会换掉那个 lock → `cannot release un-acquired lock`。3.14 上不暴露，3.11~3.13 必炸。修法：`_ensure_open` 里存下旧 lock 再装回去 |

## 六、常用命令

```bash
# 测试（运行版 / 仓库版都要跑）
cd "$LOCALAPPDATA/hermes/plugins/job-radar" && python -m unittest discover -s tests
cd "<repo>/src/job_radar" && python -m unittest discover -s tests

# 提交前检查（测试 + 脱敏 + 仓库卫生）
bash scripts/dev.sh check

# 单独跑
bash scripts/check-sensitive.sh     # 脱敏扫描
bash scripts/check-repo.sh           # 仓库卫生 + 副本漂移
bash scripts/dev.sh sync-desktop     # 桌面半边同步
bash scripts/dev.sh logs 50          # 看运行日志

# 插件体检
hermes plugins doctor "$LOCALAPPDATA/hermes/plugins/job-radar" --ci

# 抓取
BB="$LOCALAPPDATA/hermes/tools/bb-browser/bb.sh"
"$BB" site zhaopin/search "前端" --city 653 --json
"$BB" site zhaopin/detail <jobId> --json
"$BB" site boss/search "前端" --city 101210100 --json

# 登录态
hermes plugins list
```

## 七、沟通约定

- **中文**，短、直接。先给结论，细节按需。
- **任何聊天窗单条消息 ≤50 字符**；更长就按句子拆多条依次发。
- 群聊以聊天为主，不发 `.md`/附件。
- 要证据不要断言 —— 单条日志推不出结论。
- 用户说「不用核实」就别重复核实。
- 失败/中断的命令留下的产物要在同一步清掉。

## 八、别做的事（已经在 ROADMAP 里，这里再强调一次）

| 不做 | 为什么 |
| --- | --- |
| 让插件自己登录招聘网站 | 复用用户浏览器的登录态更真实，也不碰密码 |
| 把评分改成调 LLM | 本地规则够用，不烧 token，行为可预测 |
| 绕过招聘站风控 | IP 不会因为独立 profile 而改变，被限流了该降速 |
| 自动投递（无确认） | 投递不可逆，必须用户点头 |
| 简历文件发给大模型 | 个人信息外泄风险 |
| 把站点 adapter 放进公开仓库 | 里面有写操作，公开等于邀请别人用你的账号乱来 |
