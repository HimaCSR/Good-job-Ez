四、风险控制清单

① 风控是最需要盯的
BOSS 抓太频繁会弹验证码。缓解：每次请求后随机停顿 12~32 秒、单次运行条数封顶、 写操作每日上限 10 条、PAUSE 文件随时可停。被限流时第一件事是加大间隔，不是加并发。
② IP 不会因为独立 profile 而改变
独立 Chrome profile 只隔离登录态和 cookie，出口 IP 仍是同一个。 这一点必须提前说清楚，不能暗示能隐藏。
③ 投递是不可逆动作
三道门：allow_apply 开关（默认关）→ 一次性确认令牌（5 分钟、绑定 job_id） → 每日上限。没点头就不会发出去。
④ 简历不编造
prompt 里写死「只能用 profile.yaml 里真实经历中出现过的内容」，并要求每条 bullet 标注 「← 依据：」。生成物不会自动使用，你要自己看过才算数。
⑤ 简历文件不走大模型
上传的 .docx / .pdf 只在本地用规则解析（段落结构 + 字段关键词抽取）， 不发给任何模型，避免个人信息外泄。解析结果填成草稿，用户确认后才写入。
例外：「AI 根据经历推荐」按钮传的是从经历里提取的方向词， 不是原始简历文件，可以调大模型。这两条路径必须分开实现，别混了。
⑥ 投递参数下沉到每个平台
风控与安全配置按平台分开存（BOSS 是打招呼上限，智联是投递上限， 还有各自的专属项）。不存在一个全局开关覆盖所有站 —— 某站的限流规则和另一站根本不一样，用一个滑杆管全部站迟早出事。
⑦ 社区 adapter 会被覆盖
~/.bb-browser/sites/（私有）优先级高于 bb-sites/（社区）。 所有我自己写的、尤其带写操作的 adapter，都放私有目录，社区更新不会改掉行为。

七、设置页规格（2026-10-26 用户确认后定稿）

UI demo：job-radar/设置页-demo.html。五个模块，主题跟随 Hermes。

模块内容后端要点
个人信息 简历文档导入 / 身份信息 / 期望条件 / 技能 / 真实经历 ① 简历文档导入：.docx/.pdf/.txt 上传后本地规则解析（段落结构 + 字段关键词抽取）， 不走大模型，避免简历内容外泄。解析结果是草稿，用户确认后才写入。
② 身份信息：照片 / 姓名 / 电话 / 邮箱 / 学历 / 院校 / 专业 / 毕业时间。 不参与打分，只在生成简历时填模板抬头。只存本地。
③ 期望城市：改成多选（标签数组），命中任一城市即算符合城市项。
④ 岗位方向 / 技能 / 搜索关键词：除手工添加外，各带一个 「✦ AI 根据经历推荐」按钮 —— 从「真实经历」文本里提取方向词。注意与简历导入不同： 这里允许调大模型，因为传出去的是经历摘要而非原始简历文件。
⑤ 期望最少年限：暂不纳入评分，字段保留但禁用，等评分模型稳定再启用。
岗位推荐 候选岗位卡（可折叠，筛选条件收进右上角「高级」） ① 评分公式改为：职位名 30 + 技能 30 + 城市 20 + 薪资 20 （去掉经验 15 分；城市、薪资权重各提 5 分）。
①b 「筛选条件」收进「今日候选」面板右上角的「高级」按钮，默认折叠。 关键词 / 分数线 / 单次抓取上限 / 请求间隔 / 每天抓取次数 全部在里面， 不再单独开一个筛选面板。
② 岗位卡折叠：默认只显示 岗位名 / 公司 / 薪资 / 地点 / 学历 / 年限 / 分数； 展开才显示命中与缺口明细。
③ 操作按钮在评分下方，三枚同行横排：
  • 简历匹配优化（原「优化这份简历」改名）→ 走第八章的四步流程
  • 投递简历（从简历优化里独立出来，与优化并列）
  • 打开岗位
④ 投递的两条路径：
  • 该岗位做过简历匹配优化 → 直接投递优化后的那份（不再问）
  • 没做过 → 弹历史简历推荐：把用户简历模块里的历史简历 按对该岗位的匹配度排序，用户挑一份投递

用户简历
（原「简历模板」模块）		 上：简历模板库 + 上传自定义模板 + 智能选模板
下：用户简历档案列表		 ① 简历模板库：4 套内置 —— classic 经典单栏、modern 现代双栏、 tech 技术极客、acad 学术风。模板可多选， 「已选 N 套」实时更新。
② 上传自定义模板（新功能）：支持 .docx / .pdf / .png / .jpg，转换后加入模板库。
  • 只有一处上传入口：模板库右下角的「＋ 上传模板」格子。 不另开上传面板，避免两处重复。
  • 选中文件后，「转换并加入模板库」按钮出现在模板库操作条上 （位置：「预览完整效果」和「保存」之间），按钮上直接显示文件名。
  • 上传说明收进模板库右上角的帮助按钮（?）， 点开是浮层，不占版面。
  • Word：解析版式参数（页边距、字号、栏数、字体、间距）→ 生成 HTML 模板。精度最高，推荐优先用。
  • PDF / 图片：按视觉还原成 HTML 底图 + 文本层的混合模板 （原图作底，文字叠在上面）。还原度取决于图片清晰度，UI 里要提示用户。
  • 转换全部在本机完成，不调大模型。
③ 模板库统一存 HTML 模板（判定）：内置和上传的都用同一份 HTML + CSS 结构， 缩略图 = 同一模板的缩小渲染。这样一套渲染器吃下所有模板， 生成简历时不必区分来源。Word 原始文件留作溯源，PDF/图片另存底图资源。
④ 智能选模板：两个开关 —— 「由 Agent 按 JD 自行推荐模板」 （读 JD 后挑版式）、「只在你勾选的模板里挑」（一个都没勾时回退到全部）。
⑤ 用户简历档案（新功能）：
  • 投递成功的简历自动存一份 PDF进这个列表
  • 自动打标签：标签来自岗位方向 + 命中技能 + 目标岗位关键词
  • 这些标签就是后续岗位简历评分推荐的依据
  • 每份记录：文件名 / 日期 / 用的模板 / 投递几家 / 几家回复 / 标签
  • 操作：预览、下载、设为默认
平台接入 登录态体检 / 平台列表（每站带「高级」）/ 全局控制 ① 风控与安全下沉到每个 adapter：不再有全局区块，每个平台展开自己的「高级」面板：
  • 允许投递简历（默认关）
  • 每日投递上限（BOSS 是「打招呼上限」，智联是「投递上限」）
  • 跳过外包 / 劳务派遣
  • BOSS 专属：遇到风控自动降速（code 37 → 间隔拉到 60 秒 + 通知）
  • 智联专属：抓取详情页开关（关掉快 3 倍但没 JD）
② 全局只留 PAUSE 总闸 和「暂缓接入的平台」提示。
③ 广西人才网、重庆人社 暂不接入，不出现在平台列表里。
日报 今日日报（首位）/ 推送内容（含高级） ① 模块顺序：「今日日报」放首位（完整明细，用户最常看的内容）， 「推送内容」放其次。
② 没有独立的「定时推送」模块。定时与推送的所有细项 （自动抓取开关、只推当天新岗位、每次最多几条、失败也通知、抓取时段） 全部整合进「推送内容」面板右上角的「高级」按钮，默认折叠。 面板标题栏只留一句摘要（例：每 6 小时 · 下次 13:02）。
③ 推送格式精简：每条消息只含 岗位名 · 城市 + 岗位链接， 不带分数、不带命中理由。一条岗位一条消息，不合并。
④ 链接不计入 50 字限制。
⑤ 日报 Markdown 文件里保留完整明细（分数、命中、缺口、链接），推送只是索引。
主题（用户 2026-10-26 明确）
设置页不提供自己的主题选择器，只跟随 Hermes：在 Hermes 设置里换皮肤， 插件 UI 同步变化。实现方式 = CSS 直接消费 Hermes 桌面的 --dt-* 变量， 宿主切皮肤时变量一变，插件页自动跟着变。
落地细节见 skill：hermes-theme-colors。

八、简历生成流程

由岗位卡上的「简历匹配优化」触发，四步，每步都能中止。

步动作约束
1读该岗位 JD 全文从已登录的浏览器取，不额外登录、不重新抓列表
2挑出 JD 核心要求技能 / 学历 / 年限 / 关键词
3对照用户经历，标出可写进简历的点 只重组用户写过的内容，不编造没出现过的经历
4按模板生成简历 模板来自「用户简历」模块；开启智能选模板时由 Agent 按 JD 挑版式
投递永远是另一道手动确认。生成 ≠ 投递。生成结果先给预览， 用户确认后才保存/导出；投递仍需单独点头。关闭「允许投递简历」时插件永远只读。

九、投递与简历档案流转（2026-10-26 新增）

「简历匹配优化」与「投递简历」拆成两个独立动作，投递会留下档案。

场景用户看到什么系统做什么
先优化，再投递
推荐路径		 点「简历匹配优化」→ 走四步流程 → 完成后点「投递简历」 该岗位标记为 optimized，投递时直接用优化后那份，不再询问。 投递成功后存 PDF + 打标签进「用户简历」
直接投递，没优化过 点「投递简历」→ 弹历史简历推荐：列出历史简历， 每份显示对该岗位的匹配分，默认选中最高分那份 用 resume_matcher.py 给每份历史简历按标签 × 岗位要求打分排序。 用户选定后投递该份，并同样存 PDF + 打标签
只有两态，不做第三种。用户自己会判断 —— 历史简历列表为空时， 弹层自然显示空列表，用户看到「没有可用简历」就明白了，不需要专门做一个 「引导去优化」的分支。少一个分支少一份逻辑。
简历标签从哪来：投递时把「目标岗位方向 + 该岗 JD 命中技能 + 岗位关键词」 打成标签存在 PDF 简历旁边。下次遇到类似岗位时，resume_matcher.py 用这些标签去打分 —— 这就是「历史简历推荐」的排序依据。 标签只从真实经历和实际命中项来，不凭空生成。
投递依然是不可逆动作。不管走哪条路径，都必须过三道门： 每站自己的「允许投递简历」开关（默认关）→ 一次性确认令牌 → 该站每日上限。 选了历史简历不等于授权投递 —— 选定后还要走确认。

十二、运行日志（2026-10-26 已落地）

出问题时能查清楚 —— 之前只有一个 runs.error 字段，多个错误挤在一起还截断。

12.1 为什么需要

之前的盲区说明
错误被吞成字符串 bbclient 把异常包成 {"error": "..."} 返回， 中间过程（请求发了没、adapter 返回什么、耗时多少）全丢
错误挤成一坨 runs.error 是 "; ".join(errors)[:300] —— 看不出是哪个站、哪个关键词出的问题
没有时间戳和耗时 抓取变慢了、被限流了，从旧日志里看不出来

12.2 两层输出

层去哪上限
插件自己的文件 <plugin-data>/job-radar/logs/job-radar.log RotatingFileHandler，5 MB × 3 份 ≈ 20 MB，到点自动轮转
标准 logging logger 名 hermes_plugins.job_radar → Hermes 的 agent.log / errors.log Hermes 自己管（5 MB × 3 / 2 MB × 2）
不造新的日志系统。Hermes 已经把插件日志收进 agent.log / errors.log，命名空间是 hermes_plugins.<模块名> —— 标准 logging 一接就进。 单独一份文件是为了排查时一眼看完，不被别的日志淹没。

12.3 埋点位置

位置记什么
bbclient.run_site 站点、参数、耗时、返回字节数、岗位条数、错误摘要
bbclient.polite_pause 这次停顿了多少秒（排查限流）
tools._fetch_site 哪个站 + 哪个关键词、抓到几条、失败原因
tools.scan 一轮总耗时、抓到 / 新增 / 命中 / 错误数
tools.daily / push 日报路径、推送条数
login_check 各站状态与凭证名字（不记值）
未捕获异常 log.exception —— 带完整堆栈

12.4 凭证打码（两条红线）

日志里绝对不能出现凭证值。
打码规则：已知凭证键（zp_at / cookie / token / authorization …）的值换成 [REDACTED]； 40 位以上随机串也打码。
不被打码的：状态描述（「已登录（凭证 zp_at），剩 12 天」）、 URL、公司名 —— 这些打了就没法排查。
坑现象与解法
值含空格 Authorization: Bearer tok_123 只打掉第一个词（Bearer）， 真 token 漏了 → 凭证键的值允许跨空格
二次打码 刚生成的 [REDACTED] 被下一轮规则再打一次 → [REDACTED]] → 负向断言 (?!\[REDACTED)
formatter 原地改 record 一个 record 依次经过多个 handler，原地改 record.msg 会让第二个 handler 看到已改内容 →「文件里打码了、stderr 里没打码」 → 复制一份 record 再改
重复写两遍 logging.getLogger(name) 拿到的是全局共享对象； 宿主和 dashboard 层各加载一次模块就 addHandler 两次 → 先看 logger.handlers 有没有
体检失败 plugins doctor 把插件复制到临时目录再清理， 日志 handler 在那儿开文件 → WinError 32 → 懒加载（第一次 emit 才开文件）+ 日志目录不跟随 plugin_data_dir()

12.5 效果

日志上线当场就抓到一个真 bug：
matcher._salary_score 的「8000-12000」分支没给 unit 赋值 → UnboundLocalError，扫描直接崩。
之前一直没暴露，因为所有岗位薪资都是打码的 **-**元； 登录后拿到真实薪资才触发。
这就是加日志的价值：堆栈直接指向行号，不用靠猜。

13.2 仓库是唯一真相源

之前运行目录和仓库是两份代码，靠人工同步 —— 迟早会漏。
现在：$HERMES_HOME/plugins/job-radar ← junction → <repo>/src/job_radar，改代码即生效。
建 junction 要先停网关（网关 import 插件时锁着目录，删不掉）。 用 scripts/dev.sh link / unlink 切换，会自动备份。
私有数据必须移出插件目录。 profile.yaml 已迁到 <plugin-data>/job-radar/profile.yaml —— 插件目录是指向 git 仓库的链接，画像放那儿会被提交上去。
日志目录也不能跟随 plugin_data_dir() —— 插件体检会把插件复制到临时目录再清理，日志文件在那儿会句柄未关。

13.3 仓库即运行副本（junction 模式）

agent 半边是 junction：
<hermes>/plugins/job-radar → 仓库 src/job_radar

改代码即生效，不用手工同步副本。实测：仓库里写文件，运行目录立刻可见。
桌面半边是副本，必须手动同步

桌面半边在 src/job_radar/desktop/（Hermes 的「统一包」形态）： Electron 把它复制到 desktop-plugins/job-radar/， 并盖上 .hermes-package.json marker， 让 Plugins 页能把它跟 agent 行配对显示、共用一个开关。

改完仓库里的 desktop/plugin.js，要跑 bash scripts/dev.sh sync-desktop。 check-repo.sh 会检查这份副本有没有漂移。
代价：桌面端默认禁用

有 marker → Hermes 判定它是「统一包的桌面半边」→ defaultEnabled: false → 要去 Settings ▸ Plugins 手动打开一次。

换来的是：一个开关管两半、Plugins 页里配对显示、 plugins remove 会连带清理桌面半边。 曾经试过把桌面半边拆出去单独放（src/desktop/job-radar/） 来绕过这个 —— 能默认启用，但 Plugins 页变成两个条目、 卸载会留孤儿目录。用户选了保持统一包形态。
备份不能放在 plugins/ 里 —— 桌面端会扫那儿每个目录， 残留的 job-radar.bak-* 会触发 duplicate id 加载失败。 现在备份统一放 <hermes>/plugin-backups/。

十四、简历匹配优化落地（T14/T15 已实现，2026-10-27）

第八、九章是设计规格；这一章记录实际实现和实现过程中改掉的判断。

14.1 三个新模块

文件职责
resume_template.py 4 套内置模板（classic / modern / tech / acad）， 共享一份 HTML 骨架 + CSS 变量
resume_builder.py JD → 要求 → 经历证据 → 模板渲染，四步本地流程，不调 LLM
resume_store.py Chrome headless 导出 PDF；简历档案 + 标签；历史简历 × 岗位匹配分
缩略图和实际输出同源。模板预览不是另画一张图， 是用同一份 HTML 渲染的 —— 不会出现「预览好看、导出来不一样」。

14.2 铁律：每条经历都能追溯

生成结果的每一条 bullet 都带 ← 依据：经历第 N 条 的定位， 原始片段另存在 basis_text。

正式输出默认隐藏标注（那是预览用的），预览态可开。 原始片段不贴进简历 —— 它和 bullet 是同一句话， 重复一遍没有信息量，还把简历撑得很长。

用户不具备的技能一律进 gaps，不编造、不暗示具备。 自动化测试里有一条专门断言：所有生成的 bullet 必须逐字出现在用户写过的原文里。

14.3 解析上踩过的坑

问题根因处理
JD tags 粘连
CSSJavaScriptERP		 招聘站的 tags 字段不加分隔符 按已知技能名切分（SKILL_ALIASES）+ camelCase + 全大写边界三层兜底

14.4 JD 从哪来

列表页不返回 JD。描述、要求、学历、年限全在详情页。

所以优化流程会按需抓一次详情页（bbclient.fetch_detail）， 抓完写回岗位表。抓到之前不做任何匹配。

14.6 PDF 输出

@page { size: A4; margin: 14mm 16mm; } 决定纸面大小和留白。 屏幕预览另给一份 @media screen 的内边距， 打印时 @page 会再算一次，两者不冲突。
