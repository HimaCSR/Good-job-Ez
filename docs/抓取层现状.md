### 三个必须记住的坑

1. **profile 在 `<你的 Chrome profile 路径>`，不是用户目录下的 `<your-chrome-profile>`。**
   查法：Chrome 里打开 `chrome://version`，看「个人资料路径」和「命令行」。
   Cookies 文件在 `Default\Network\Cookies`（新版 Chrome 位置，不是 `Default\Cookies`）。

2. **wrapper 必须用绝对路径调 node。**
   PATH 里的 `node` 解析到的是 node 14（没有 `fetch`，bb-browser 直接报
   「Cannot find a Chromium-based browser」）。
   正确写法：`exec "$LOCALAPPDATA/hermes/tools/node-26.7.0-win32-x64/node.exe" ...`

3. **daemon 要用 `BB_BROWSER_CDP_URL=http://127.0.0.1:9222` 连你的 Chrome。**
   已固化在 wrapper 里。不设这个变量，bb-browser 会去找/起自己的浏览器，
   那个浏览器没有你的登录态。

"$BB" daemon stop

"$BB" open "https://www.zhaopin.com/sou/?kw=前端"     # 打开页面
"$BB" tab list                                          # 看 tab id
"$BB" site boss/search "前端" --city 101210100 --json   # 跑 adapter
"$BB" eval "表达式" --tab <tabId>                      # 在页面里执行 JS
"$BB" network requests --filter joblist --with-body --json --tab <tabId>
"$BB" screenshot "路径.png" --tab <tabId>
```

### 踩过的坑

1. **tab id 会失效** — daemon 重启后必须重新 `tab list`，用新 id。
2. **跨域 fetch 失败** — 智联 API 在 `fe-api.zhaopin.com`，页面在 `www.zhaopin.com`，
   同源策略拦住。adapter 的 `@meta.domain` 必须等于实际要调的那个 host。
3. **相对路径** — adapter 里 `fetch('/api/x')` 才是同源；写绝对 URL 会被拒。
4. **BOSS 的 `zp_st`** — 接口要一个反爬 token，是页面 JS 现算的。
   照抄请求没用（页面自己也返回 code 37）。要么让页面正常访问（解决风控），
   要么用别的站。

## 登录态会不会丢？（2026-10-26 实测）

**不会。** 实测流程：Chrome 完全关闭 → 重启 → 两个站照常抓。

**证据**

| 检查 | 结果 |
| --- | --- |
| Chrome 关闭后 cookie 库能否读 | 能，81920 bytes（运行时被锁，关掉后可读） |
| 落盘的登录凭证 | `zp_at`（BOSS）、`at`/`rt`（智联）、`__zp_stoken__`、`wt2` 全在磁盘上 |
| 重启后 BOSS | `code 0`，15 条，薪资正常（16-22K） |
| 重启后智联 | 20 条，**薪资不再打码**（1.6-2.1万） |

**各站登录凭证的寿命**（从 cookie 的 expires_utc 读出来）

| 凭证 | 站 | 有效期 |
| --- | --- | --- |
| `zp_at` / `wt2` / `wbg` | BOSS | 12 天 |
| `__zp_stoken__` | BOSS | 3 天（风控 token，最短） |
| `at` | 智联 | 7 天 |
| `rt` | 智联 | 30 天 |
| `x_passport_sid` | 智联 | 会话级（但持久化在库里，关浏览器仍在） |
| `x-zp-device-sn` | 智联 | 1 天（设备指纹，刷新即续） |
| `huibo_device_token` | 汇博 | 74 天 |

**结论**

- 关 Chrome、再开 → 登录态还在，**不用重新登录**。
- 但 **BOSS 的 `__zp_stoken__` 只有 3 天**，它是风控 token；过期后 adapter 会退回 code 37，
  这时需要在浏览器里手动搜一次（会重新签发），**不是重新登录**。
- 智联 `at` 7 天、`rt` 30 天 → 半个月到一个月要重新登录一次。
- 长期不管的结果：BOSS 报「您的环境存在异常」，智联薪资重新变成 `**-**元`。

**要不要做自动续期？**

可以：定期用已登录态访问一次站点，刷新短寿命 cookie（如 `x-zp-device-sn`）。
但 `zp_at`/`at` 这种真正的登录凭证没法自动续——服务端说了算。
所以更实际的做法是：**插件检测到 401/code 37 时明确告诉你「去浏览器搜一下」，而不是默默失败。**


## 登录态体检（已实装进插件）

工具名：`job_radar_login`

```
✓ BOSS直聘 — 已登录（凭证 zp_at）（约 3 天）
    → 风控凭证 __zp_stoken__ 约 3 天后过期；过期后在浏览器搜一次即可续期，无需重新登录
✓ 智联招聘 — 已登录（凭证 at、rt）（约 7 天）

代码位置：
- `login_check.py` — 凭证 → 状态/剩余天数的判定逻辑（纯函数，可单测）
- `browser_cookies.py` — 通过 CDP `Storage.getCookies` 读 cookie（不落盘、不进日志）

**踩坑：`Network.getAllCookies` 在 browser target 上返回 0 个 cookie。**
必须用 `Storage.getCookies`（browser 级 API），实测能拿到 142 个。

**禁用自带皮肤选择器**，只同步 UI 状态，不覆盖颜色。

demo 文件：`<PROJECT>\设置页-demo.html`

**自检坑**：深色皮肤光看截图会误判成「没生效」（深色被当成深蓝黑）。

`getComputedStyle(document.documentElement).getPropertyValue('--dt-background')`

### 简历模块 → 用户简历

拆成两块：

**上：简历模板**
- 4 套内置（classic / modern / tech / acad）+ 一个「＋上传模板」格
- **新增上传自定义模板**：`.docx` / `.pdf` / `.png` / `.jpg`
  - Word → 抽版式参数 → 生成 HTML 模板（精度最高）
  - PDF/图片 → HTML 底图 + 文本层混合模板
  - **本机转换，不调大模型**
- 智能选模板两个开关

**下：用户简历档案**
- 投递成功的简历自动存 PDF + 打标签
- 每份：文件名 / 日期 / 模板 / 投递几家 / 几家回复 / 标签
- 操作：预览 / 下载 / 设为默认
- 标签 = 后续岗位简历评分推荐的依据

### 关键判定：模板库统一存 HTML

内置和上传的模板用**同一份 HTML + CSS 结构**，缩略图 = 同一模板的缩小渲染。
这样一套渲染器吃下所有模板，生成简历时不必区分来源。
Word 原件留作溯源，PDF/图片另存底图资源。

（另一种做法是模板库存 Word，但那样缩略图要另做渲染、
生成时要处理 docx 排版，两套渲染逻辑维护成本翻倍 —— 不划算。）

### 投递三态

| 场景 | 行为 |
| --- | --- |
| 优化过 | 直接投优化版，不再问 |
| 没优化过 + 有历史简历 | 弹历史简历推荐，按匹配分排序 |
| 没优化过 + 无历史简历 | 引导去优化，不投递 |

不管哪条路，都还要过三道门：站点开关（默认关）→ 一次性令牌 → 每日上限。

**重排章节时把内容吃掉了。** 用 `find()` 定位 + 切片重排 HTML，
`</body>` 和后半章节被 `tail_idx` 算错切没了。
→ 改 HTML 结构时，**先备份**，或者用「按 h2 起点切段再拼接」而不是手工算偏移。
这次靠前面几轮 execute_code 的输出才把内容找回来。
